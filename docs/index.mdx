Zeabur Builder turns a Git repository into an image that can run. It finds the language your code is in with [Railpack](https://railpack.com) (Node.js, Python, Go, PHP, Ruby, Java, Rust, Elixir, Deno, .NET, Gleam, C++, Zig, static sites and shell scripts), builds your Dockerfile, or has a model write one with the [AI builder](builds/ai-builder.mdx), and builds again when the branch changes.

## I use Zeabur OSS

Zeabur OSS installs and runs Zeabur Builder for you. You don't need to install or configure it yourself.

- Zeabur Builder is a component from the Zeabur Catalog. If your cluster doesn't have it, open **Cluster** → **Components**, find Zeabur Builder and click **Install**. See [View and install cluster components](https://oss.zeabur.com/docs/zeabur/cluster/components/).
- To deploy from Git, open a project and select **Add** → **Deploy from Git**. See [Build and deploy a service from Git](https://oss.zeabur.com/docs/zeabur/deploy/git/).

The rest of Zeabur OSS, from installing it on a server to running your services, is in the [Zeabur OSS documentation](https://oss.zeabur.com/docs/zeabur/).

## I use Zeabur Builder on its own

Zeabur Builder is a Kubernetes operator. You create a `Build` that points to a Git repository. Zeabur Builder builds an image for each new commit, pushes the image to a registry, and writes `<repository>:<tag>@<digest>` to `status.latestImage` for your rollout tool.

Zeabur Builder only builds images. Your pipeline, deployment tool, and log collector handle testing, deployment, and log storage.

<Callout type="info">

The API is `v1alpha1`. Read the [changelog](../CHANGELOG.md) before you upgrade.

</Callout>
