---
title: 创建第一个 Build
description: 创建指向 Git 仓库的 Build，查看每个新 commit 构建出的镜像和构建结果。
---

创建一个 `Build` 指向 Git 仓库，控制器就会为每个新 commit 构建镜像，并将结果写入 `status.latestImage`。

<Steps>

<Step>

### 创建 Build

在集群中创建以下 `Build`，使用 `dockerfile` 构建器构建 Git 仓库中的 Dockerfile：

```yaml
apiVersion: builder.zeabur.com/v1alpha1
kind: Build
metadata: {name: whoami, namespace: team-a}
spec:
  source: {git: {url: https://github.com/traefik/whoami}}
  builderRef: dockerfile
```

示例省略了 `ref`，因此会跟踪仓库的默认分支。你可以从 `status.resolvedRef` 查看控制器解析出的分支。

`builderRef` 支持两个构建器：

| 构建器 | 用途 |
| --- | --- |
| `dockerfile` | 构建仓库中的 Dockerfile。 |
| `railpack` | 使用 [Railpack](https://railpack.com) 为没有 Dockerfile 的仓库规划构建。生成的镜像以 UID 1000 运行，可在 Pod Security `restricted` 下启动。 |

需要传入构建变量时，使用 `spec.env`。你可以直接指定值，也可以从 Secret 的 key 获取值。Zeabur Builder 会通过 BuildKit secrets 将这些值传入构建。

</Step>

<Step>

### 查看构建状态和日志

在 `Build` 所在的 Namespace 执行：

```sh
kubectl get builds
kubectl get buildruns
```

`kubectl get builds` 显示每个 Build 的构建器、来源、修订版本和就绪状态。加上 `-o wide` 可查看镜像：

```sh
kubectl get builds -o wide
```

`kubectl get buildruns` 显示每次构建的阶段、原因、开始时间和结束时间。

构建日志位于该次构建 Job 的 Pod 日志中。查看该 Pod 的日志，即可读取构建输出。

</Step>

</Steps>

## 确认结果

构建完成后，控制器会将镜像推送到镜像仓库（registry）的以下路径：

```text
<registry.host>/<namespace>/<name>
```

`status.latestImage` 会记录镜像，格式如下：

```text
<repository>:<tag>@<digest>
```

每次构建都有自己的标签（tag），由分支、Unix 时间和 commit 组成，例如：

```text
main-1761058800-3e1a9c2
```

部署工具可以按这个格式排序，较新的构建排在后面。你可以用 `spec.output.tagTemplate` 和 `extraTags` 调整标签。

获取镜像后，你可以接着配置[部署构建好的镜像](../builds/rollout.mdx)。
