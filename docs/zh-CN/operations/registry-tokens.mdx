镜像仓库（registry）只信任一把 Ed25519 密钥，只有控制器能读取这把密钥。控制器为每次使用签发限定仓库、有有效期的令牌（token）。你可以用令牌上传源代码归档，管理员也能推送不属于任何 Build 的镜像。

## 令牌类型与有效期

| 类型 | 权限与范围 | 有效期 |
| --- | --- | --- |
| run | 推送与拉取镜像仓库 `<namespace>/<build>`，以及拉取源代码归档仓库 `<namespace>/<build>/source`。 | Job 的运行时限加上 10 分钟。 |
| upload | 推送到源代码归档仓库 `<namespace>/<build>/source`。 | 15 分钟。 |

如果 Build 的镜像位于 `registry.host`，但仓库路径不属于该 Build，构建就会失败。其他 registry 的镜像使用推送用的 Secret，详见[推送到外部镜像仓库](../builds/external-registries.mdx)。

## 上传源代码归档

### 开始前

- 准备 `kubectl` 和 [ORAS](https://oras.land)。
- 确认你有编辑目标 Build 的权限。
- 确认 ORAS 能连接到 `zot.zot.svc:5000`，并信任 Secret `zot/zot-tls` 中的 CA。从集群外上传时，使用下方的 port-forward 方式。

<Steps>

<Step>

### 申请 upload 令牌

将 Build 上的 annotation `builder.zeabur.com/upload-token-request` 设为新值。控制器会创建 Secret `<build>-upload`，并在 `.status.uploadToken.request` 中返回这次请求的值。

```sh
kubectl -n team-a annotate build/api --overwrite builder.zeabur.com/upload-token-request=u1
kubectl -n team-a wait build/api --for=jsonpath='{.status.uploadToken.request}'=u1
```

上传完成前，可以不设置 `archive.digest`。这时 Build 会等待上传，`SourceReady` 显示 `WaitingForUpload`。

</Step>

<Step>

### 使用 ORAS 上传

如果 ORAS 能直接连接到集群内的 registry，读取 Secret 中的认证配置后上传：

```sh
kubectl -n team-a get secret api-upload -o jsonpath='{.data.\.dockerconfigjson}' |
  base64 -d > auth.json
oras push --registry-config auth.json zot.zot.svc:5000/team-a/api/source:upload-1 \
  --artifact-type application/vnd.zeabur.source.v1+tar \
  source.tar.gz:application/vnd.oci.image.layer.v1.tar+gzip
```

从集群外上传时，先启动 port-forward：

```sh
kubectl -n zot port-forward svc/zot 5000:5000
```

将 Secret 的 `token` 字段提供给 `localhost:5000`，并保留 TLS：

```sh
printf '{"auths":{"localhost:5000":{"registrytoken":"%s"}}}' \
  "$(kubectl -n team-a get secret api-upload -o jsonpath='{.data.token}' | base64 -d)" > auth.json
kubectl -n zot get secret zot-tls -o jsonpath='{.data.ca\.crt}' | base64 -d > ca.crt
oras push --registry-config auth.json --plain-http=false --ca-file ca.crt \
  localhost:5000/team-a/api/source:upload-1 ...
```

上方的 `...` 代表直连示例中的 artifact type 与源文件参数。

</Step>

<Step>

### 设置源代码 digest

将 `archive.digest` 设为 `oras push` 输出的 digest。

</Step>

</Steps>

## 管理员推送镜像

管理员可以从控制器的 Pod 获取令牌，不必创建 Build：

```sh
TOKEN=$(kubectl -n builder-system exec deploy/zeabur-builder -- \
  /zeabur-builder registry-token --repository zeabur_admin/tools --push)
printf '{"auths":{"zot.zot.svc:5000":{"registrytoken":"%s"}}}' "$TOKEN" > auth.json
oras push --registry-config auth.json zot.zot.svc:5000/zeabur_admin/tools:v1 ./file
```

这类镜像的仓库路径应避开 `<namespace>/<name>` 格式。例如，第一段名称可以包含 Namespace 名称不允许的 `_` 或 `.`。否则，控制器会在清理时删除这些镜像。

## 清理镜像与源代码

删除 Build 时，无论单独删除还是随 Namespace 一起删除，控制器都会删除下列仓库及其所有标签（tag）：

- `<namespace>/<build>/source`
- `<namespace>/<build>`

控制器会处理删除事件，也会在启动时及每 10 分钟扫描 registry 的仓库目录，补上遗漏的清理。因此，控制器会在 Build 删除后的一个扫描周期内移除镜像。

控制器运行期间，管理员可以使用 `registry-token --delete` 获取令牌，再用 `DELETE /v2/<repository>/manifests/<digest>` 手动删除镜像。

<Callout type="warn">

在 Zot 中，手动删除镜像仓库的所有标签，也会删除其下的仓库，包括 `<repository>/source` 中的源代码归档。

</Callout>

## 轮换密钥

zot 只在启动时读取一次公钥。

<Callout type="warn">

registry 重启后，旧密钥签发的令牌会立即失效。运行中的构建会失败，之后可以重新构建。

</Callout>

<Steps>

<Step>

### 删除签名密钥 Secret

使用 Zeabur Catalog 的 Zot 时，执行：

```sh
kubectl -n zot delete secret zot-token-signer
```

</Step>

<Step>

### 等待新密钥

等待 cert-manager 签发新的 Secret。

</Step>

<Step>

### 重启 registry

```sh
kubectl -n zot rollout restart statefulset/zot
```

</Step>

</Steps>

## 权限

Helm chart 会在密钥所在的 Namespace 中添加 Role，只授予该 Secret 的 `get` 权限。

控制器使用现有的 Secret 权限写入 `<build>-upload` Secret。

## 已知限制

- **删除 Build 不会撤销令牌**。令牌过期前会持续有效。run 令牌能在清理后再次推送镜像，控制器会在下一次扫描时删除这些镜像。
- **令牌绑定仓库名称，不绑定 Namespace UID**。删除 Namespace 后，如果有人创建同名 Namespace，旧 Namespace 的 run 令牌过期前，仍能推送到新 Namespace 的仓库。使用默认 Job 运行时限时，最长为 70 分钟（60 分钟加上 10 分钟）。将已删除的 Namespace 名称交给另一个团队前，先等待 70 分钟。
