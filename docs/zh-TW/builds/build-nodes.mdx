title: 在建置節點上建置
description: 用標籤和 taint 留一個節點專門建置，讓建置不佔用執行應用程式的節點。
source: "8020f5686ed0"
---

預設每次建置最多使用 1 個 CPU 和 1 GiB 記憶體（`buildkitd.resources.limits`）。在節點都不大的叢集上，這些資源會從應用程式那邊分走。如果有一台空出來的機器，可以把它設成建置節點：每個 Namespace 的 buildkitd 和每個建置 Job 都在這台機器上執行，其他工作負載不會排到這裡。建置不再佔用應用程式的 CPU 和記憶體，每個 Namespace 的建置快取也都留在這台機器的磁碟上。

buildkitd 只會建置所在節點架構的映像檔，所以建置節點的 CPU 架構必須和執行應用程式的節點相同。

<Steps>

<Step>

### 幫節點加上標籤和 taint

taint 讓其他工作負載不會排到這個節點，標籤讓建置只排到這個節點，兩者都要設定。只設 toleration，建置還是可能排到任何節點；只設 node selector，建置會因為 taint 而無法在這個節點啟動。

```sh
kubectl label node build-1 builder.zeabur.com/builds=true
kubectl taint node build-1 builder.zeabur.com/builds=true:NoSchedule
```

</Step>

<Step>

### 設定 chart 參數

在 values 檔加上下面的內容，再執行 `helm upgrade`：

```yaml
builds:
  nodeSelector: {builder.zeabur.com/builds: "true"}
  tolerations:
    - {key: builder.zeabur.com/builds, operator: Equal, value: "true", effect: NoSchedule}
```

兩個值都留空時，建置會排到排程器挑選的任何節點。控制器本身會留在原本的節點。

</Step>

</Steps>

## 變更後的第一次建置

Namespace 的 buildkitd 正在建置時，控制器不會移動它。等 buildkitd 閒置夠久、縮減到零，控制器會把它連同快取一起刪除，這個 Namespace 下一次建置時，會在建置節點上重新建立。

所以變更後，每個 Namespace 的第一次建置都從空的快取開始。變更快取大小（`--buildkitd-cache-size`）、Namespace 的建置資源上限，或升級到會變更 buildkitd 的 Zeabur Builder 版本時，也是一樣。

## 確認建置在哪裡執行

開始一次建置，再列出這個 Namespace 的 buildkitd、建置 Pod 和所在節點：

```sh
kubectl -n builder-system get pod -o wide -l builder.zeabur.com/namespace=team-a
kubectl -n team-a get pod -o wide
```

`NODE` 欄位應該顯示建置節點。
