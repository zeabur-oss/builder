---
title: 建置私有儲存庫
description: 使用 credentialsRef 或 GitHub App，讓 Build 取得私有儲存庫的程式碼並觸發建置。
---

你可以用 `spec.source.git.credentialsRef` 指定 Secret，搭配 basic-auth 權杖或 ssh-auth deploy key 存取私有儲存庫。使用 deploy key 時，必須搭配 `known_hosts`，Secret 也必須加上指定標籤。私有 GitHub 儲存庫也可以使用 GitHub App，讓 Build 取得短效 installation 權杖。

## 使用 credentialsRef

將 `spec.source.git.credentialsRef` 指向存放認證資訊的 Secret。Secret 支援以下兩種型別：

| Secret 型別 | 內容 |
| --- | --- |
| `kubernetes.io/basic-auth` | `username`，以及當作 `password` 的權杖。用於 `https://` 網址。 |
| `kubernetes.io/ssh-auth` | `ssh-privatekey`（deploy key）與 `known_hosts`。用於 SSH 網址。 |

在 Secret 加上以下標籤：

```yaml
builder.zeabur.com/git-credentials: "true"
```

## 使用 GitHub App

叢集管理員只需建立一次 GitHub App，並將設定存到控制器的 Namespace。接著，在 Build 指定要使用的 installation。

<Steps>

<Step>

### 建立 GitHub App 並設定可用的 Namespace

執行以下指令。`zeabur-builder github-app create` 會在 127.0.0.1 開啟 manifest 流程：

```sh
zeabur-builder github-app create --webhook-url https://<host>/hooks/github-app \
  > github-app.json   # opens the manifest flow on 127.0.0.1
kubectl -n builder-system apply -f github-app.json
kubectl -n builder-system create configmap github-app-installations \
  --from-literal=12345678=team-a,team-b   # installation id: namespaces allowed to use it
```

在 `github-app-installations` ConfigMap 中，鍵是 installation ID，值是允許使用該 installation 的 Namespace。上例允許 `team-a` 與 `team-b` 使用 installation 12345678。

把 App 安裝到擁有要建置儲存庫的帳號。installation ID 是安裝設定頁網址 `https://github.com/settings/installations/<id>` 最後的數字。

</Step>

<Step>

### 在 Build 指定 installation

在 Build 的 `spec.source.git.githubApp` 填入 installation ID。Git 網址必須是 `https://`，也不能同時設定 `credentialsRef`：

```yaml
spec:
  source:
    type: git
    git:
      url: https://github.com/acme/private-api
      githubApp: {installationId: 12345678}
```

</Step>

</Steps>

GitHub App 會提供短效 installation 權杖，讓 Job 以唯讀權限存取私有儲存庫。每個 commit 都會收到 commit status。想讓狀態的 **Details** 連結打開顯示這個 Build 的頁面（例如你的控制台），在 Build 加上註解 `builder.zeabur.com/details-url`，值設成該頁面的 `http` 或 `https` 網址。

App 的 push 事件會喚醒對應的 Build，不需要為每個 Build 設定 Secret。控制器有接收 webhook 時，這些 Build 改為每 10 分鐘輪詢一次，而不是每分鐘。其他觸發方式請見[觸發建置](./triggers.mdx)。

## 子模組

Job 會依儲存庫記錄的 commit 抓取 Git 子模組。子模組和儲存庫在同一個 `https://` 主機時，會使用同一個權杖，來源是 `credentialsRef` 或 GitHub App。其他主機上的子模組拿不到權杖，所以必須是公開的。deploy key 會用在 `known_hosts` 裡的每個 SSH 主機。

子模組抓取失敗時，`fetch` 步驟會失敗，訊息會寫出該子模組的路徑。
