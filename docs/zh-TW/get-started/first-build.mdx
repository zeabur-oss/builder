---
title: 建立第一個 Build
description: 建立指向 Git 儲存庫的 Build，檢視每個新 commit 建置出的映像檔與建置結果。
---

建立一個 `Build`，指定 Git 儲存庫。控制器就會為每個新 commit 建置映像檔，並將結果寫入 `status.latestImage`。

<Steps>

<Step>

### 建立 Build

先建立建置用的 Namespace，再建立以下 `Build`，使用 `dockerfile` 建置器，依照 Git 儲存庫中的 Dockerfile 建置映像檔：

```sh
kubectl create namespace team-a
kubectl apply -f - <<'EOF'
apiVersion: builder.zeabur.com/v1alpha1
kind: Build
metadata: {name: whoami, namespace: team-a}
spec:
  source: {type: git, git: {url: https://github.com/traefik/whoami}}
  builderRef: dockerfile
EOF
```

`kubectl` 會印出 `build.builder.zeabur.com/whoami created`。

這個範例沒有指定 `ref`，因此會追蹤儲存庫的預設分支。你可以檢視 `status.resolvedRef`，確認控制器解析出的分支。

`builderRef` 支援這些建置器：

| 建置器 | 用途 |
| --- | --- |
| `dockerfile` | 依照儲存庫中的 Dockerfile 建置映像檔。 |
| `railpack` | 使用 [Railpack](https://railpack.com) 為沒有 Dockerfile 的儲存庫規劃建置流程。產出的映像檔使用 UID 1000 執行，可在 Pod Security `restricted` 下啟動。 |
| `agent` | [AI 建置器](../builds/ai-builder.mdx)：另外兩個建置不了時，由模型寫一份 Dockerfile。要在 chart 啟用後才能用。 |

需要傳入建置變數時，請使用 `spec.env`。你可以直接指定值，也可以從 Secret 的 key 取值。Zeabur Builder 會使用 BuildKit secrets，將這些值傳入建置流程。

</Step>

<Step>

### 檢視建置狀態與日誌

檢視 Build 和每次建置：

```sh
kubectl -n team-a get builds
kubectl -n team-a get buildruns
```

`kubectl get builds` 會顯示每個 Build 的建置器、來源、修訂版本與就緒狀態。加上 `-o wide` 就能檢視映像檔：

```sh
kubectl -n team-a get builds -o wide
```

`kubectl get buildruns` 會顯示每次建置的階段、原因、開始時間與結束時間。

等第一次建置完成。建置快取還是空的時候，可能要幾分鐘：

```sh
kubectl -n team-a wait --for=condition=Ready build/whoami --timeout=15m
```

預期輸出：

```text
build.builder.zeabur.com/whoami condition met
```

逾時的話，`kubectl -n team-a get buildruns` 會顯示每次建置的階段和原因。

每次建置的日誌都在該次建置 Job 的 Pod 日誌中。建置步驟每行輸出一個 JSON 事件，內含步驟名稱、花費秒數，以及該行來自 stdout 還是 stderr。想當成文字讀，執行 `kubectl -n team-a logs <pod> | jq -r '.text // .message // .name'`。

</Step>

</Steps>

## 確認結果

建置完成後，控制器會將映像檔推送到 registry 的以下路徑：

```text
<registry.host>/<namespace>/<name>
```

控制器會在 `status.latestImage` 記錄映像檔，格式如下：

```text
<repository>:<tag>@<digest>
```

印出映像檔的完整名稱：

```sh
kubectl -n team-a get build whoami -o jsonpath='{.status.latestImage}{"\n"}'
```

輸出會像 `<registry.host>/team-a/whoami:main-1761058800-3e1a9c2@sha256:…`。

每次建置都有自己的 tag，由分支、Unix 時間與 commit 組成，例如：

```text
main-1761058800-3e1a9c2
```

部署工具可以根據這個格式排序，較新的建置會排在後面。你可以用 `spec.output.tagTemplate` 與 `extraTags` 調整 tag。

取得映像檔後，可以接著設定[部署建置好的映像檔](../builds/rollout.mdx)。
