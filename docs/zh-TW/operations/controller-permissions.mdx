請把控制器當成叢集管理員。

## 控制器能做什麼

控制器的 ServiceAccount 有以下權限：

- 在所有 Namespace 建立 Job。
- 讀寫所有 Namespace 的 Secret。
- 在 `builder-system` 建立 StatefulSet，其中的 Pod 可使用特權模式。

取得控制器或其權杖的人，也能執行這些操作。

## 兩個 ValidatingAdmissionPolicy 的限制

Helm chart 提供兩個 ValidatingAdmissionPolicy，用來限制控制器的 ServiceAccount 能建立哪些資源。

### Job 政策

`<release>-zeabur-builder-jobs` 只允許建立符合建置 Job 規格的 Job：

- 映像檔只能使用 `jobImage`、`railpackImage` 與 `admissionPolicy.extraImages`。
- 不允許使用特權模式、額外的 capabilities，也不允許使用主機的網路、PID、IPC、連接埠或路徑。
- 只能使用該 Namespace 的 `default` ServiceAccount，且不帶權杖。
- 不得在 `kube-*` Namespace、控制器所在的 Namespace、registry 所在的 Namespace，或 `admissionPolicy.extraDeniedNamespaces` 中的 Namespace 建立 Job。

### StatefulSet 政策

`<release>-zeabur-builder-buildkitd` 只允許在控制器所在的 Namespace 建立 StatefulSet：

- 映像檔只能使用 `buildkitdImage`。
- 不允許使用主機的 Namespace、連接埠或路徑。

## 政策擋不住的事

政策無法阻止讀取允許建置的 Namespace 中的 Secret。建置 Job 可以掛載該 Namespace 中的任何 Secret。

## 檢視與編輯政策

這些政策都是一般的 Kubernetes 物件，你可以用 `kubectl` 檢視與編輯。

<Steps>

<Step>

### 檢視政策與綁定

```sh
kubectl get validatingadmissionpolicy,validatingadmissionpolicybinding
```

</Step>

<Step>

### 編輯 Job 政策

```sh
kubectl edit validatingadmissionpolicy builder-zeabur-builder-jobs
```

</Step>

</Steps>

<Callout type="warn">

`helm upgrade` 會依照 chart values 重新寫入政策，覆寫你直接編輯的內容。

</Callout>

## 使用自訂 ClusterBuilder

如果自訂 ClusterBuilder 使用其他 planner 映像檔，就必須將該映像檔加入 `admissionPolicy.extraImages`。
