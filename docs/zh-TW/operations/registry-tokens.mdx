registry 只信任一把 Ed25519 金鑰，只有控制器能讀取這把金鑰。每次使用時，控制器都會簽發權杖，限定可存取的倉庫和有效期限。你可以用權杖上傳來源封存檔，管理員也能推送不屬於任何 Build 的映像檔。

## 權杖類型與時效

| 類型 | 權限與範圍 | 時效 |
| --- | --- | --- |
| run | 推送與拉取 registry `<namespace>/<build>`，以及拉取來源封存檔倉庫 `<namespace>/<build>/source`。 | Job 的執行期限加上 10 分鐘。 |
| upload | 推送到來源封存檔倉庫 `<namespace>/<build>/source`。 | 15 分鐘。 |

如果 Build 的映像檔位於 `registry.host`，但倉庫路徑不屬於這個 Build，建置就會失敗。如果映像檔位於其他 registry，則使用推送時所需的 Secret。詳見[推送到外部 registry](../builds/external-registries.mdx)。

## 上傳來源封存檔

### 開始前

- 準備 `kubectl` 和 [ORAS](https://oras.land)。
- 確認你有編輯目標 Build 的權限。
- 確認 ORAS 能連到 `zot.zot.svc:5000`，並信任 Secret `zot/zot-tls` 中的 CA。從叢集外上傳時，請使用下方的 port-forward。

<Steps>

<Step>

### 申請 upload 權杖

將 Build 上的 annotation `builder.zeabur.com/upload-token-request` 設為新值。控制器會建立 Secret `<build>-upload`，並在 `.status.uploadToken.request` 回報這次請求的值。

```sh
kubectl -n team-a annotate build/api --overwrite builder.zeabur.com/upload-token-request=u1
kubectl -n team-a wait build/api --for=jsonpath='{.status.uploadToken.request}'=u1
```

上傳完成前，可以先不設定 `archive.digest`。這時 Build 會等待上傳，`SourceReady` 會顯示 `WaitingForUpload`。

</Step>

<Step>

### 使用 ORAS 上傳

如果 ORAS 能直接連到叢集內的 registry，先讀取 Secret 中的認證設定，再上傳：

```sh
kubectl -n team-a get secret api-upload -o jsonpath='{.data.\.dockerconfigjson}' |
  base64 -d > auth.json
oras push --registry-config auth.json zot.zot.svc:5000/team-a/api/source:upload-1 \
  --artifact-type application/vnd.zeabur.source.v1+tar \
  source.tar.gz:application/vnd.oci.image.layer.v1.tar+gzip
```

從叢集外上傳時，先開啟 port-forward：

```sh
kubectl -n zot port-forward svc/zot 5000:5000
```

使用 Secret 的 `token` 欄位向 `localhost:5000` 認證，並保留 TLS：

```sh
printf '{"auths":{"localhost:5000":{"registrytoken":"%s"}}}' \
  "$(kubectl -n team-a get secret api-upload -o jsonpath='{.data.token}' | base64 -d)" > auth.json
kubectl -n zot get secret zot-tls -o jsonpath='{.data.ca\.crt}' | base64 -d > ca.crt
oras push --registry-config auth.json --plain-http=false --ca-file ca.crt \
  localhost:5000/team-a/api/source:upload-1 ...
```

上方的 `...` 代表直接連線範例中的 artifact type 與來源檔案參數。

</Step>

<Step>

### 設定來源 digest

將 `archive.digest` 設為 `oras push` 輸出的 digest。

</Step>

</Steps>

## 管理員推送映像檔

管理員可以從控制器的 Pod 取得權杖，不必建立 Build：

```sh
TOKEN=$(kubectl -n builder-system exec deploy/zeabur-builder -- \
  /zeabur-builder registry-token --repository zeabur_admin/tools --push)
printf '{"auths":{"zot.zot.svc:5000":{"registrytoken":"%s"}}}' "$TOKEN" > auth.json
oras push --registry-config auth.json zot.zot.svc:5000/zeabur_admin/tools:v1 ./file
```

這類映像檔的倉庫路徑應避開 `<namespace>/<name>` 格式。例如，可以在第一段名稱中加入 Namespace 名稱不允許的 `_` 或 `.`。否則，控制器會在清理時刪除這些映像檔。

## 清理映像檔與來源

不論單獨刪除 Build，或連同 Namespace 一起刪除，控制器都會刪除下列倉庫及其所有 tag：

- `<namespace>/<build>/source`
- `<namespace>/<build>`

控制器會處理刪除事件，也會在啟動時及每 10 分鐘掃描 registry 的倉庫目錄，清理先前遺漏的資料。因此，刪除 Build 後，控制器會在一個掃描週期內移除映像檔。

控制器運作期間，管理員可以使用 `registry-token --delete` 取得權杖，再用 `DELETE /v2/<repository>/manifests/<digest>` 手動刪除映像檔。

<Callout type="warn">

在 Zot 中，手動刪除 registry 的所有 tag，也會刪除其下的倉庫，包括 `<repository>/source` 中的來源封存檔。

</Callout>

## 輪替金鑰

zot 只在啟動時讀取一次公鑰。

<Callout type="warn">

registry 重新啟動後，舊金鑰簽發的權杖會立即失效。執行中的建置會失敗，之後可以重新建置。

</Callout>

<Steps>

<Step>

### 刪除簽署金鑰 Secret

如果使用 Zeabur Catalog 的 Zot，請執行：

```sh
kubectl -n zot delete secret zot-token-signer
```

</Step>

<Step>

### 等待新金鑰

等待 cert-manager 簽發新的 Secret。

</Step>

<Step>

### 重新啟動 registry

```sh
kubectl -n zot rollout restart statefulset/zot
```

</Step>

</Steps>

## 權限

Helm chart 會在金鑰所在的 Namespace 新增 Role，只授予該 Secret 的 `get` 權限。

控制器使用既有的 Secret 權限寫入 `<build>-upload` Secret。

## 已知限制

- **刪除 Build 不會撤銷權杖**。權杖在到期前仍然有效。持有 run 權杖的人可以在清理後再次推送映像檔，控制器會在下一次掃描時刪除這些映像檔。
- **權杖綁定倉庫名稱，不綁定 Namespace UID**。刪除 Namespace 後，如果有人建立同名 Namespace，舊 run 權杖到期前，還是能推送到新 Namespace 的倉庫。使用預設 Job 執行期限時，權杖最長可有效 70 分鐘（60 分鐘加上 10 分鐘）。將已刪除的 Namespace 名稱交給另一個團隊前，請先等待 70 分鐘。
